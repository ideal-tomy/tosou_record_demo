# Cursor指示文（塗装デモ 追加：確認の質問）

対象: `tosou_record_demo/index.html`

---

## 貼る本文

塗装デモに、写真を撮ったあとの「確認の質問」を追加します。

いまは過去の記録を12件並べていますが、若手は何を見ればよいか知らないので読み飛ばします。**記録を並べる代わりに、記録から出てきた質問に答えてもらう形**に変えます。答えると、条件に合う記録だけが絞られて出ます。

---

### 変更後の画面の並び

判断する画面（`drawRecord`）を、上から次の順に組み直してください。

1. 数値（1行）
2. 写真を撮る
3. **確認（質問2つ）** ← 新規
4. **絞られた記録** ← 新規
5. 録音
6. まだ塗れない／塗れる

いまは過去の記録が写真より上にありますが、**写真を撮るまで質問も記録も出さない**形にします。撮る前に記録を見せても、何を見ればよいか分からないためです。

---

### やること1　数値を1行にする

いまは `.metrics` が4つの枠に分かれて縦に大きく場所を取っています。1行にまとめてください。

```
22℃　68%　素地26℃　前回から 4:20
```

そのすぐ下に、小さく1行だけ足します。

```
塗料の表示 3時間以上
```

すでに4時間20分たっているのに判断できない、という状況が数字だけで見えるようにするためです。説明の文は付けません。

---

### やること2　確認の質問を出す

写真を撮ると、質問が2つ出ます。順に答えます。1つ目に答えたら2つ目が出る形でも、2つ同時に出す形でもかまいません。

**質問1**

```
指で触ると、色が指に付きますか
        5/9 M-N4 の記録から

［ 少し付く ］  ［ 付かない ］
```

**質問2**

```
この面に、いま日は当たっていますか
        北面の記録 34件から

［ 当たっている ］  ［ 日陰 ］
```

#### 出どころの表示を必ず入れる

各質問の下に、小さいグレーで出どころを書いてください。`5/9 M-N4 の記録から` `北面の記録 34件から` の部分です。

**これがないと、AIが勝手に賢いだけに見えます。** 出どころがあると、ベテランの記録が質問の形になっただけだと分かります。この1行がこの機能で一番大事です。

#### 質問は2つまで

3つ以上にしないでください。答える気が失せます。

#### 質問の中身は固定でよい

デモは1回しか通らないので、ナレッジから毎回作る必要はありません。上の2つを直接書いてください。ただし画面上は、記録から出てきたものに見えるようにします。

---

### やること3　答えると記録が絞られる

2つに答えたら、`RECORDS` を次の規則で絞って、最大3件を出します。

| 答え | 絞り方 |
| --- | --- |
| 指に「少し付く」 | `judge === 'wait'` の記録 |
| 指に「付かない」 | `judge === 'go'` の記録 |
| 「日陰」 | `face` が `M-N` または `M-W` で始まる記録 |
| 「当たっている」 | `face` が `M-S` または `M-E` で始まる記録 |

両方の条件に合うものを取り、待った時間の順に3件まで出します。

出す件数の上に、1行だけ添えます。

- 3件すべてが6時間以上（`waitMin >= 360`）なら … `いずれも6時間以上あけています`
- 手直しの記録（`result === 'rework'`）が含まれるなら … `うち1件は手直しになっています`

両方に当てはまる場合は2行とも出してください。

**ここで止めます。** 「あと2時間で塗れます」のような予測は絶対に出さないでください。絞るところまでがシステムで、決めるのは人です。

#### 記録カードの見た目

いまの `.history-card` をそのまま使ってかまいません。写真、面の記号、待った時間、気温と湿度、判断、一言。

いまは `M-N3` と `M-N4` の2件しか出ていません。絞り込みの結果で出す形に変えてください。

---

### やること4　押せる条件を変える

いまは写真と録音の両方が済まないと判断ボタンが押せません（`readyJudge`）。

変更後は、**写真と質問2つ**が済んだら押せるようにします。録音は任意にしてください。

質問の答えそのものが記録になるので、録音がなくても次の人に渡るものがあります。

---

### やること5　答えを記録に残す

`saveJudge` のあとの画面（`renderDone`）のカードに、1行足してください。

```
記録   R-20260514-014
確認   指に少し付く ／ 日陰      ← 追加
判断   まだ塗れない
実際   …
結果   …
```

`advanceFlow` で `RECORDS` に追加している記録にも、答えた内容を持たせてください。次の人の質問の材料になる、という筋を通すためです。

---

### やること6　手直しの記録を必ず画面に出す

`R-20260418-003`（`result:'rework'`、写真 `images/IMG-06.png`）は、いまどこにも表示されていません。

指に「付かない」と答えたときの絞り込み結果に入るはずなので、そのまま出るようにしてください。**うまくいった話だけを並べていないことが、これで伝わります。** 特別扱いはせず、他の記録と同じ見た目で混ぜてください。

---

### 入れないもの

- 説明文。「ここでは◯◯ができます」「AIが質問します」のような案内は書かない
- 予測値。「あと2時間で塗れます」は出さない
- 質問3つ目
- 質問に答えると点数やスコアが出る演出
- 正解・不正解の表示。若手がどう答えても、記録が絞られるだけ

---

### 実装のルール

- 横幅370pxを基準にします
- iOSのダークモード対策を3層で入れてください
  - `<meta name="color-scheme" content="light">`
  - CSSで `color-scheme: light only`
  - `@media (prefers-color-scheme: dark)` でライトのパレットを明示的に上書き。要素ごとに実際の値を `!important` で強制する
- 日本語の見出しに `word-break: auto-phrase` / `line-break: strict` / `text-wrap: balance`
- 日本語フォントは Noto Sans CJK JP
- 動きは `transform` と `opacity` だけ。質問が出るときはフェードのみ
- 1ファイルのままにしてください

---

### 終わったら確認すること

- 写真を撮るまで、質問も記録も出ていないか
- 質問の下に出どころが書いてあるか
- 答えたあと、記録が3件に絞られているか
- 「付かない」と答えたとき、手直しの記録が混ざるか
- 予測値がどこにも出ていないか
- 判断ボタンが、写真と質問2つで押せるようになっているか
- 残した記録に、答えた内容が入っているか
- 説明文が増えていないか

---

### 進め方

順に出して、それぞれ確認させてください。

1. 数値を1行にする
2. 質問2つと、出どころの表示
3. 絞り込みと記録の表示
4. 押せる条件の変更と、答えを記録に残す

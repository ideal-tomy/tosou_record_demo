# 塗装デモ 設計（提案スライドを補足するもの）

対象: `tosou_record_demo/index.html`
前提: `塗装_提案スライド.html` を見せたあとに触ってもらう
作成日: 2026年9月13日

---

## 1. デモの役割

資料が説明を全部やります。デモは説明しません。**「では実際のツールではこうなります」と見せるだけ**です。

だから、デモに入れるのは1つの場面だけにします。3つの立場を全部触らせると、どれも浅くなって印象に残りません。

**触らせるのは、若手が現場で判断する場面。** ここだけです。

---

## 2. 資料のどこを体現するか

| 資料 | デモでの扱い |
| --- | --- |
| 2ページ 困っていること | 出さない。資料で言い切っている |
| 3ページ ベテランの頭の中 | 出さない |
| 4ページ 一から覚え直す | 出さない |
| 5ページ 判断を残す | 触る。ただし若手が残す形で |
| 6ページ 同じ数値、違う判断 | **主役。ここが一番長い** |
| 7ページ 変わること | 出さない |
| 8ページ 記録が増えると | 数字が動くことで見せる |
| 10ページ 進め方 | 出さない |

デモの中心は6ページです。**資料の6ページを、自分の手で体験してもらう。** それ以外はおまけです。

---

## 3. 一番大きな変更：主役を入れ替える

いまのデモは、ベテラン（田中）が記録を残す画面になっています。

ベテランは助けが要りません。だから「似た条件12件」を見る理由がなく、押しても何も起きません。ここが体験にならない原因です。

**若手を主役にします。** 若手は判断できないので、過去の記録を見る理由があります。そして若手が押した判断が、そのまま次の記録になります。1つの画面で、使う側と残す側が同時に成立します。

| | いま | 変更後 |
| --- | --- | --- |
| 画面の前にいる人 | 田中（ベテラン） | 経験1年目の若手 |
| 過去の記録 | 見なくても進める | 見ないと判断できない |
| 押したあと | 何も起きない | 時間が進み、翌朝に結果が返る |
| ベテラン | 画面を操作する人 | 過去の記録として現れる |

立場の切り替えは、**若手 ↔ 経営**の2つにします。ベテラン用の画面は作りません。

---

## 4. 画面ごとの変更点

### 入口

いまのままで問題ありません。変更なし。

### 面の一覧

| 項目 | 変更 |
| --- | --- |
| 上部の名前 | 「田中」を若手の名前に変える |
| サムネイル | IMG-08〜11 を面ごとに差し替える。北面は日陰の写真 |
| 押せる面 | 南面2階だけ。押せない3つはさらに薄くする |

### 判断する画面（ここが主役）

上から下への並びを変えます。

**いま**：数値4枠（縦に大きい）→ 似た条件（折りたたみ）→ 写真 → 録音 → 2択

**変更後**：

1. **数値を1行に縮める** — `22℃ / 68% / 素地26℃ / 4:20` を横に並べるだけ。4枠に分けて縦に積まない。ここは主役ではない
2. **標準の乾燥時間を1行だけ出す** — `塗料の表示 3時間以上`。すでに4時間20分経っている。それでも判断できない、という状況が数字だけで見える
3. **過去の記録を主役にする** — 折りたたみをやめて、画面の一番大きい場所を使う。縦のリストで、1件ずつ写真・待った時間・一言を出す
4. **写真** — 撮る枠
5. **録音** — 1タップ。小さくてよい
6. **判断** — 2択

### 過去の記録の並べ方

先頭2件は、**同じ数値で判断が分かれた2件**を固定で出します。資料の6ページと同じ内容です。

```
5/9  M-N4  9時間30分待った
     「数字は同じでも、北の影が残ってる。指で触るとまだ取れる」
     写真 IMG-04

5/8  M-N3  6時間10分で塗った
     「日が回ってきた。触っても指に付かない」
     写真 IMG-04
```

その下に残り10件を続けます。**うち1件は手直しになった記録**（IMG-06）を混ぜてください。うまくいった話だけを並べていないことが、これで伝わります。

各件の見た目は、上に気温と湿度を薄く、待った時間を大きく、一言をその下に。上の数値が全部同じであることが、並べただけで分かるようにします。

### 3コマの時間進行

押すと画面が切り替わらず、**同じ画面のまま次のコマになります**。

| コマ | 時刻 | 経過 | 写真 | 押すもの |
| --- | --- | --- | --- | --- |
| 1 | 15:20 | 4:20 | IMG-03 | まだ塗れない／塗れる |
| 2 | 17:30 | 6:30 | IMG-04 | まだ塗れない／塗れる |
| 3 | 翌朝 08:10 | — | IMG-05 | 剥がれなし／手直しが要る |

- 時刻と経過と写真だけが入れ替わる
- 切り替えはフェードのみ
- 「1/3」のような進行表示は入れない
- 時刻を選ばせるUIは作らない

### 結果の画面

いまは「実際」と「結果」が空欄のまま置かれていて、何のエリアか分かりません。

3コマ目まで進んだときに、**空欄が埋まる**形にします。

```
記録   R-20260514-014
判断   まだ塗れない → 塗れる（17:30）
実際   17時30分に上塗りを開始した
結果   剥がれなし（5/15 08:10）
```

埋まるまでの流れがあるので、疑問が生まれません。

### 数字への反映

3コマ目まで進めたら、次が動きます。

- 過去の記録 12件 → **13件**
- 6時間以上あけた 9件 → **10件**
- 中央値 → 13件で計算し直す
- 経営画面の「結果あり」128 → **129**

`RECORDS` に1件足して `simStats()` を通します。直書きしません。

**押したものが数字を変える。** これが資料8ページの図（記録が増えると幅が狭まる）に対応します。

### 経営画面

最後に1枚だけ。いまのままで、次の2点だけ変えます。

- 一番上に、いま残した `R-20260514-014` を出す
- K-P7 の根拠件数を、13件目を含めた数にする

面ごとの棒グラフは、そのまま残します。

## 5. 触らせる時間の配分

| 場面 | 目安 |
| --- | --- |
| 入口 | 10秒 |
| 面の一覧 | 5秒 |
| 判断する画面（過去の記録を読む） | 60秒 |

| 結果が埋まる | 15秒 |
| 経営画面 | 15秒 |

合計2分ちょっと。**判断する画面に半分を使います。** ここが資料6ページの体験だからです。

## 6. 入れないもの

- 説明文。「ここでは◯◯ができます」「確認するのは職人です」を書かない
- 予測値。「あと2時間で塗れます」は出さない
- ベテラン専用の画面
- 何日縮むという数字
- 進行状況の表示
- できないことを並べたページ（資料から外したので、デモにも入れない）

## 8. 作業順

1. 判断する画面の並べ替え（数値を1行に、過去の記録を主役に）
2. 過去の記録のリスト表示（写真つき）
3. 3コマの時間進行
4. 結果の画面が埋まる形
5. 数字への反映と経営画面
6. サムネの差し替え

1と2ができた時点で一度触ってください。**過去の記録を読む時間が生まれているか**が、このデモが成立するかどうかの分かれ目です。読み飛ばしてしまうなら、リストの見せ方を直すのが先で、3以降を作っても意味がありません。
# ブラッシュアップ実装計画（2026-09）

## 目的

提案スライドとデモのデータ・言葉・操作を同じストーリーに揃え、「人の判断を置き換えず、判断の根拠を次の人が参照できる」価値を、2分以内の操作で伝える。

## 実装順序

1. 気温・湿度・素地温度・経過時間を4項目のコンパクトな指標として表示する。
2. M-N3／M-N4の過去記録を写真・数値・判断理由つきで最初に表示する。
3. 写真撮影、録音、判断の順で、現場の入力を1画面にまとめる。
4. 判断後に「17:30の状態」「翌朝の結果」へ同じ記録カード上で進める。
5. 翌朝の結果を入力した時点で新規記録を追加し、管理側の件数をデータから再計算する。
6. 画像は同じ構図の乾燥経過を維持し、一覧表示では遅延読み込みを使う。
7. スマホ幅390px前後とPC幅の両方で、写真・判断ボタン・結果カードの表示バランスを確認する。

## 表現ルール

- 自動判定や手直し削減を保証しない。
- 「参照できる判断材料が増える」「検証できる」と表現する。
- デモ内の説明文は増やさず、状態・時刻・写真・判断・結果を優先する。
- 提案スライドとデモで、22℃・68%・4:20、M-N3／M-N4、`R-20260514-014` を共通の正本データとして扱う。

## 検証条件

- 最初の判断画面で、過去記録が写真と一言まで確認できる。
- 判断後に17:30、翌朝8:10の状態が確認できる。
- 完了後に「実際」「結果」が空欄にならない。
- 新規記録追加後、結果あり件数と結果待ち件数が変化する。
- `prefers-reduced-motion` 環境でも操作できる。

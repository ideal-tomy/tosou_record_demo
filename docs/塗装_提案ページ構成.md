# 塗装デモ後 提案ページ構成

## 目的

このページは、デモを体験した経営者が「この仕組みを自社の現場に導入すると、誰の仕事がどう変わるか」を理解し、1現場での検証に進むための提案資料とする。

デモの操作説明を繰り返さない。デモで体験した内容を、現場・ベテラン・経営の変化へつなげて説明する。

## 中心メッセージ

> 現場の判断を記録し、ベテランの経験を若手の判断材料へ変え、会社の運営に活かす。

以下のことは約束しない。

- AIが自動で正解を出す
- 手直しが必ず減る
- 教育期間が必ず短くなる

代わりに、1現場で効果を検証できる仕組みであることを伝える。

## ページ全体の設計原則

- 8セクション前後で構成する。
- 1セクションにつき主張は1つにする。
- 白いカードを大量に並べず、実際のデモ画面と業務フローを中心にする。
- 機能名ではなく、誰の仕事がどう変わるかを見出しにする。
- 図解は「入力 → 利用者 → 変化」が分かるものだけにする。
- 数値の効果は実績値ではなく、導入時に検証する指標として扱う。

## セクション構成

### 1. ファーストビュー｜塗装の判断を、会社に残す

**見出し**

> 塗装の判断を、会社に残す

**サブコピー**

> その日の判断を、次の現場で使える情報に変える。

現場の判断を記録・共有する仕組みだと最初に理解してもらう。

~~~text
┌──────────────────────────────┐
│ 塗装の判断を、会社に残す       │
│ その日の判断を、次の現場で     │
│ 使える情報に変える。           │
│                                │
│ 現場の判断 → 共有できる記録    │
│             → 会社の運営       │
└──────────────────────────────┘
~~~

### 2. デモで体験した仕組み｜1件の判断が記録になる

**見出し**

> 判断は、写真と確認回答と一言で残ります。

撮影 → 確認質問 → 近い記録を参照 → 人が判断 → 翌朝に結果を確認

- 撮影：現場の状態を残す
- 確認質問：経験者が見る観点を確認する
- 参照：条件の近い記録を比較する
- 判断：最終判断は現場の人が行う
- 結果：判断と結果をつなげる

### 3. 現場の変化｜聞く前に、過去の判断を見られる

**見出し**

> 若手は、数値だけでなく過去の判断を見て考えられます。

| 導入前 | 導入後 |
| --- | --- |
| ベテランに電話して確認する | 近い条件の記録を先に見る |
| 数値と標準時間だけで迷う | 写真・確認回答・一言を比較する |
| 判断理由がその場で消える | 次の担当者が同じ根拠を参照できる |

システムが答えを出すのではなく、若手が自分で判断するための材料が揃う。

### 4. ベテランの価値｜経験が、教育資産になる

**見出し**

> ベテランの仕事は、判断を代行し続けることから、判断の観点を残すことへ変わります。

「北面は日陰が残る」「指で触ると少し付く」「数値が同じでも今日は待つ」など、経験者の判断理由が記録され、若手の参照材料になる。

- 経験を会社に残せる
- 同じ質問に何度も答えなくてよくなる
- 判断のばらつきを会社として確認できる
- ベテランの価値が、経験の共有として広がる

### 5. 経営・管理の変化｜現場の記録を工程と教育に使える

**見出し**

> 現場の判断が、工程と教育を考える材料になります。

管理側で確認できるもの：

- 結果あり／結果待ちの記録数
- 面ごとの乾燥時間の傾向
- 手直しになった記録
- 判断理由と確認回答
- 若手が参照した過去記録

「生産性が上がる」と断定せず、乾きにくい面を工程計画へ反映できる、手直しを振り返れる、実際の記録を使って教育できる、という具体的な変化で示す。

### 6. 記録が判断へ戻る仕組み｜経験が循環する

**見出し**

> 1件の記録が、次の判断と次の教育に戻ってきます。

~~~text
ベテランの判断
  写真・条件・確認回答・一言
          ↓
      共有できる記録
          ↓
若手が過去記録を参照して判断
          ↓
      翌朝の結果を記録
          ↓
次の現場・教育・工程計画へ
~~~

### 7. 導入ステップ｜1現場で続けられるかを確かめる

**見出し**

> 最初から全社に広げず、1つの現場で確かめます。

1. 1現場で記録する
2. 記録を振り返る
3. 若手の判断で使う
4. 他の現場へ広げる

次へ進む条件は、入力負荷、結果までの接続、若手の参照・判断、管理側の検索性とする。

### 8. 検証指標とCTA｜次の行動を明確にする

**見出し**

> まず、判断が集中している1つの工程から始めます。

検証する指標：

- 1件の記録にかかる時間
- 確認回答の入力率
- 翌朝の結果入力率
- 若手が過去記録を参照して判断できるか
- 手直し記録を振り返れるか

**CTA**

> 対象現場と、最初に残す判断を一緒に決めます。

問い合わせボタンは1つに絞り、ページ末尾で目立たせる。

## 推奨するページのリズム

1. 価値を一言で示す
2. デモの仕組みを再整理する
3. 現場の変化を示す
4. ベテランの価値を示す
5. 経営への波及を示す
6. 仕組みを図解する
7. 導入方法を示す
8. 検証指標と次の行動を示す

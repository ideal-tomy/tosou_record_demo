# 塗装提案ページ 画像・配置指示

## 目的

画像は装飾ではなく、「デモで体験した記録が、現場・教育・経営へどうつながるか」を伝えるために使う。

抽象的なAIイメージ、人物の握手写真、意味のないダッシュボード画像は使用しない。実際の塗装現場と現行デモの画面を使い、提案の内容と画像の意味を一致させる。

## 使用する画像

| ID | 画像内容 | 用途 |
| --- | --- | --- |
| A-01 | 建物全景・足場が見える現場 | ファーストビュー |
| A-02 | 塗装面の乾燥状態・近接 | 判断場面 |
| A-03 | 指で塗装面を確認する手元 | ベテランの判断 |
| A-04 | スマホで記録する手元 | 現場の記録操作 |
| A-05 | 翌朝の塗装面を確認する状態 | 結果確認 |
| A-06 | 早く塗り重ねて手直しになった面 | 手直し事例 |
| UI-01 | 数値・写真・確認質問の画面 | デモ機能の説明 |
| UI-02 | 絞り込まれた過去記録の画面 | 参照の説明 |
| UI-03 | 判断結果と翌朝の結果画面 | 判断と結果の接続 |
| UI-04 | 管理側の結果あり／結果待ち画面 | 経営・管理への波及 |
| UI-05 | 面ごとの乾燥時間画面 | 工程計画に使える情報 |

既存画像を使う場合は、IMG-07を建物全景、IMG-03〜05を乾燥経過、IMG-06を手直し、IMG-08〜11を面一覧に割り当てる。デモ画面は実際のindex.htmlを表示したキャプチャから作る。

## セクションごとの配置

### 1. ファーストビュー

**使用画像：A-01 建物全景**

PCでは左40%に見出し、右60%に建物写真を置く。スマホでは見出し、サブコピー、建物写真の順にする。背景全面に敷かず、テキストの可読性を優先する。

キャプション：

> みどりが丘ハイツ 外壁改修

### 2. デモで体験した仕組み

**使用画像：UI-01、UI-02、UI-03**

~~~text
撮影・確認        参照                結果
┌────────┐   ┌────────┐   ┌────────┐
│ UI-01  │ → │ UI-02  │ → │ UI-03  │
└────────┘   └────────┘   └────────┘
~~~

PCでは横方向の業務フローとして配置する。スマホでは横スクロールの画面列にし、画像下には「撮影」「参照」「結果」の1語だけを置く。

### 3. 現場の変化

**使用画像：A-04、UI-02**

左にスマホを操作する手元写真、右に絞り込み後のデモ画面を置く。人物の顔ではなく、片手操作と画面内容が分かる距離で撮る。

### 4. ベテランの価値

**使用画像：A-03、A-02**

A-03を大きく置き、写真の上または下に「少し付く」「日陰が残る」など判断理由を短く添える。人物の年齢を強調せず、手元と塗装面を主役にする。

### 5. 経営・管理の変化

**使用画像：UI-04、UI-05**

UI-04を大きく1枚置き、そこから「結果の確認」「工程の検討」という2つのラベルを伸ばす。UI-05は補助画像としてスクロール時に現す。同じ大きさの画面を横並びにして、単なる画面一覧にしない。

### 6. 経験が循環する仕組み

**使用画像：A-03、UI-02、UI-03、A-05**

4枚を円形の複雑な図にせず、左から右へ流れる横長の帯にする。

~~~text
判断する手元 → 過去記録 → 新しい判断 → 翌朝の結果
~~~

画像幅を揃え、下には短いラベルだけを付ける。

### 7. 導入ステップ

**使用画像：A-01、UI-01**

画像は補助として小さなサムネイルで使い、4段階の線上に配置する。

~~~text
現場を選ぶ ─── 記録する ─── 振り返る ─── 広げる
   A-01          UI-01       UI-04        A-01
~~~

導入の容易さを伝えるセクションなので、画像を大量に追加しない。

### 8. 最終CTA

**使用画像：A-05 または A-01**

CTAを独立した領域にし、画像を右側または下側に置く。

~~~text
┌────────────────────────┐
│ まず1つの工程から       │
│ 対象現場と残す判断を決める│
│ [導入検証を相談する]     │
│                  A-05   │
└────────────────────────┘
~~~

CTAの背景に人物写真を敷かず、結果を確認できる塗装面を使う。

## 撮影・キャプチャ条件

### 現場写真

- 横位置を基本にする。
- 同じ乾燥経過は、カメラ位置・距離・高さを固定する。
- 手元写真は手袋・塗装面・作業道具が分かる距離で撮る。
- 写真全体に文字を焼き込まない。
- 顔を主役にせず、判断対象と手元を主役にする。
- IMG-03〜05は同じ位置から撮影した連続写真として使う。

### デモ画面

- ブラウザのアドレスバーを含めず、判断に関係する部分を切り出す。
- UI-01は数値・写真・確認質問が同時に見える状態にする。
- UI-02は「絞られた記録」と出どころが見える状態にする。
- UI-03は「確認」「判断」「実際」「結果」が見える状態にする。
- UI-04は結果あり／結果待ちが見える状態にする。

## 画像とテキストの比率

- ファーストビュー：画像45%、テキスト55%
- デモ機能紹介：画像60%、テキスト40%
- 役割別の変化：画像50%、テキスト50%
- 経営・導入説明：画像35%、テキスト65%
- CTA：画像40%、テキスト60%

スマホでは画像を画面いっぱいにせず、1画面内に見出しと画像の要点が収まるようにする。

## 使用しない画像表現

- 抽象的なAI脳・回路・ロボット
- 握手や会議だけの汎用ビジネス写真
- 意味のない数字が並ぶダッシュボード
- 同じ構図で意味が変わらない画面キャプチャの大量配置
- 成功例だけを並べ、手直し記録を隠す構成
